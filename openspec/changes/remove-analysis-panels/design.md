## Context

参见 [proposal.md](./proposal.md) 与 [spec.md](./specs/chart-analysis-display/spec.md)。当前交易机会功能跨越 Dashboard、前端 API、Go 路由/handler/service/repository/model 和 SQLite。`backend/internal/database` 只为该功能初始化 `data/opportunities.db` 与 `opportunities` 表；工作区当前存在 `backend/data/opportunities.db`。该专用数据库不承载其他表或业务数据。

`Dashboard.vue` 还会在后台定时请求 `/api/opportunities` 并显示通知；`SimpleChart.vue` 从分析结果绘制支撑/压力位线和摘要。前端 `package.json` 当前没有自动化测试脚本或组件测试依赖。项目维护规则要求行为修改先通过失败测试验证，因此实现时需要先建立可重复的前端组件测试入口，并为 API 退役和本地数据清理添加后端行为测试。

## Goals / Non-Goals

**Goals:**
- 主页面保留 K 线、交易对/周期选择和行情状态，不渲染分析面板或交易机会功能。
- 移除支撑/压力位图表标记、浏览器后台轮询和完整的机会 API/检测/持久化链路。
- 升级时删除旧的专用交易机会数据库，并确保新版启动不再创建它。
- 先通过失败测试证明待移除功能仍存在，再验证移除后的行为。

**Non-Goals:**
- 不删除仍被 K 线、行情或其他后端分析功能使用的分析能力。
- 不改变行情数据、实时连接状态或交易对/周期选择。
- 不迁移或保留交易机会历史记录；数据按用户确认删除。
- 不调整 ATR 等当前仍属于行情图表区域的信息。

## Decisions

1. **从 Dashboard 移除分析面板和交易机会交互。** 删除六类分析组件及机会按钮、弹窗、通知状态、后台定时器和请求调用，不用 CSS 隐藏。这样不再产生未显示的 UI 或后台机会流量。
   - 备选方案：只隐藏按钮和面板。该方案会继续运行机会轮询并保留用户不可见的功能链。

2. **从 SimpleChart 移除支撑/压力位展示数据流。** 删除对应的图表摘要、水平线标记及仅供其使用的 props、计算值和样式；保留 K 线、价格和 ATR 信息。
   - 备选方案：保留 props 并用开关或样式关闭。该方案留下已经退役的展示路径。

3. **删除交易机会的完整后端纵向功能，并移除旧 API。** 删除 `/api/opportunities` 路由、handler、检测 service、repository、机会专用模型与数据库初始化；旧路径自然返回 404，不提供空响应兼容层。其他分析 API 与确有剩余消费者的分析代码继续保留。
   - 备选方案：保留兼容 endpoint 返回空数组。用户已确认移除整个模块和计算，该方案会留下已退役的公共表面。

4. **通过启动清理退役专用数据库文件。** 后端启动时以固定的旧数据库路径执行幂等文件删除；文件不存在时继续正常启动。此数据库只包含机会数据，因此删除文件即可删除全部历史记录，且比保留空表更符合用户确认的范围。
   - 备选方案：仅停止写入或只清空表。这样会保留旧机会数据文件或记录，不符合已确认的数据删除要求。

5. **先写并运行前后端行为测试，再实现移除。** 前端测试覆盖面板和机会入口缺席、没有轮询请求、图表无支撑/压力位标记；后端测试覆盖旧 API 返回 404、清理会删除包含测试数据的旧数据库文件、后续启动不会创建文件。测试使用临时目录中的数据库文件，不触碰工作区现有数据库。
   - 备选方案：只运行编译和构建。它们不能验证旧功能消失，也不能验证用户数据被删除。

## Risks / Trade-offs

- 删除 `/api/opportunities` 会破坏仍调用它的外部客户端 → 在 proposal 明确标记 BREAKING，更新部署说明并验证该路径返回 404。
- 删除 `opportunities.db` 不可逆，回滚旧代码也无法恢复历史机会 → 启动清理仅作用于此专用文件；用户已明确要求删除，测试以临时数据库验证目标路径与清理行为。
- 新增前端测试依赖及后端清理测试会增加少量维护成本 → 只添加必要的测试入口，且数据清理测试不得访问真实数据库文件。

## Migration Plan

升级后的后端在提供服务前删除旧版专用 `data/opportunities.db` 文件；清理成功或文件不存在时继续启动，若清理失败则报告明确错误并停止启动，避免宣称数据已删除。随后新版不再初始化 SQLite 或创建该文件。前端与后端更新后，旧 API 调用方会收到 404。此数据删除不可通过回滚恢复；回滚前必须接受机会历史数据已永久移除这一结果。
