## Purpose

将 Watchlist 定时分析筛选出的高置信度可执行方案安全、可追踪地投递到已配置的企业微信群机器人，便于用户及时查看市场机会。

## ADDED Requirements

### Requirement: 企微通知使用服务端安全配置

系统 SHALL 通过服务端配置的企业微信群机器人 Webhook 发送通知。Webhook 凭据 SHALL NOT 出现在客户端、数据库明文分析内容、错误响应或日志中。未配置 Webhook 时，定时扫描和分析结果落库 SHALL 继续工作，且通知状态 SHALL 清楚标记为未配置。

#### Scenario: Webhook 已配置
- **WHEN** 系统存在有效的服务端 Webhook 配置且存在待通知候选
- **THEN** 系统只从服务端向该 Webhook 发起通知请求

#### Scenario: Webhook 未配置
- **WHEN** 定时分析成功但没有可用 Webhook 配置
- **THEN** 所有分析结果仍持久化，相关通知状态标记为未配置，扫描服务继续工作

#### Scenario: 日志和错误处理
- **WHEN** Webhook 请求失败或返回异常
- **THEN** 日志和内部错误记录不得包含完整 Webhook 凭据，且 SHALL 保留可定位的失败类别

### Requirement: 企微消息包含可理解的方案和数据时间

每条企微通知 SHALL 使用纯文本呈现币种、左侧/右侧时机、Long/Short 方向、置信度、分析周期、入场类型与价位、止盈、止损、简短分析理由和行情数据时间。通知 SHALL 说明置信度为信号强度而非胜率；不得宣称系统已下单。没有相关行情证据的 OI 或成交量不得出现在消息中作为已知事实。

#### Scenario: 发送可执行高置信度方案
- **WHEN** 存在置信度严格大于 70 的可执行方案
- **THEN** 企微纯文本消息包含该方案的核心价位、左/右时机、置信度和对应行情时间

#### Scenario: 按企微长度限制组织多币种消息
- **WHEN** 同一轮存在多个待发送结果或消息正文超过企微文本长度限制
- **THEN** 系统将完整的方案块按 UTF-8 字节上限拆分为多条消息，不截断单个方案的必要字段

#### Scenario: 微信客户端不可靠支持 Markdown
- **WHEN** 系统构造企业微信群机器人文本消息
- **THEN** 正文使用无需 Markdown 渲染即可阅读的纯文本

### Requirement: 企微投递成功和失败状态可追踪

系统 SHALL 使用企业微信群机器人文本消息请求格式发送内容，并检查 HTTP 状态、可解析的 JSON 响应及企微成功码 `errcode = 0`。只有确认成功的投递 SHALL 标记为已发送并参与后续去重。网络错误、无效响应或非零企微错误码 SHALL 记录为失败且不得错误地抑制后续投递。

#### Scenario: 企微确认接收消息
- **WHEN** Webhook 返回成功 HTTP 状态、有效 JSON 和 `errcode = 0`
- **THEN** 系统将通知记为成功投递，后续同一方案不重复发送

#### Scenario: Webhook 返回错误
- **WHEN** 请求失败、响应无效或 `errcode` 不为零
- **THEN** 系统将投递记为失败，不把方案标记为已通知，并在下一次合适的扫描机会重新评估投递

#### Scenario: 多条消息受速率限制
- **WHEN** 多个文本分片需要连续发送
- **THEN** 系统按企微速率限制控制请求频率，并记录每条分片的投递结果
