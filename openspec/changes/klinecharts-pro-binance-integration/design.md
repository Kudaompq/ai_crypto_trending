## Context

动机与用户可见范围见 [proposal.md](proposal.md)；需求边界见本变更的 `market-kline-chart` 和 `open-interest-chart` delta specs。

变更前前端使用 Vue 3 与 KLineCharts Core 10.0.3；兼容性验证后本变更固定为 Pro 0.1.1 + Core 9.8.7。页面协调 Binance 历史 REST、实时 SSE、备用状态、图表研究指标和浏览器本地偏好；图表组件负责 Core 绘图对象和每交易对绘图持久化。Pro 是独立的图表 UI 包，其预览默认 Datafeed 面向 Polygon，不能直接作为本项目数据源。历史分页挂接点及绘图状态访问能力按锁定版本验证。

## Goals / Non-Goals

**Goals:**

- 以完整集成图表体验替代分散的自定义周期、摘要、指标和绘图控件。
- 复用现有 Binance 数据链路并保留其实时状态、分页、切换隔离和备用语义。
- 保留现有研究指标与绘图偏好；OI 使用持仓数量字段。
- 让依赖版本、偏好迁移和 Pro/Core 交互边界可验证、可回退。

**Non-Goals:**

- 引入 Polygon 或其他行情来源，或新增后端行情接口。
- 改变 Binance 合约交易对规则、REST/SSE 协议及服务器侧订阅模型。
- 保留被移除的自定义图表摘要或在本变更中增加交易分析面板。

## Decisions

### 1. 由 Pro UI 调用项目自有 Binance Datafeed

通过 Vue 生命周期封装 Pro 的创建、更新和销毁；Datafeed 的交易对搜索仅返回项目支持的 USDⓈ-M 标的，周期映射到现有 15 个 Binance 原生周期。历史请求继续复用前端现有历史 API，并以 Pro 请求的时间区间和周期适配结果；向左翻页由图表的历史加载回调驱动，沿用现有时间游标、去重和 hasMore 语义。实时订阅桥接现有 SSE/store，取消订阅时释放对应监听；REST 备用更新与实时/非实时标记继续由现有行情协调层维护。

备选方案是使用 Pro 的默认 Datafeed，因其指向 Polygon 且数据语义与 Binance USDⓈ-M、OI 及现有实时状态不一致而排除；另造后端 Datafeed API 会重复现有历史和 SSE 链路，故不采用。

### 2. 先做版本与 API 能力验证，再锁定依赖组合

隔离验证显示 `@klinecharts/pro@0.1.1` 与 `klinecharts@10.0.3` 在 Vite 预构建阶段因缺少 `FormatDateType`、`DomPosition`、`ActionType` 和 `TooltipIconPosition` 导出而失败；与 `klinecharts@9.8.7` 组合时，实际图表可挂载、响应尺寸、切换交易对/周期并取消旧订阅。依赖固定为 Pro `0.1.1` + Core `9.8.7`，并对现有前端执行类型检查和生产构建。

Pro `0.1.1` 的公开接口没有生命周期释放或 Core Chart 访问，分页加载也把“页面非空”当成“仍有更早数据”。通过精确匹配 `0.1.1` 的安装补丁保留 Solid `render()` 返回的释放函数、公开 `getChart()`、增加 `Datafeed.hasMoreHistory()`，并将 `OPEN_INTEREST` 加入副图和无参数设置菜单。补丁运行时校验版本及每个改写点，避免静默应用到其他版本；Vue 侧只调用这些显式公开接口，不访问 Pro 私有字段。

备选方案是直接采用预览仓库中的版本号或只按 semver 声明安装；预览和应用的 Core 版本不同，单靠声明无法证明 Vue 生命周期、指标和绘图功能实际可用。

### 3. 用适配层保留 Pro 之外的行情协调职责

Pro 负责图表交互、周期栏、指标入口和绘图栏；Dashboard/store 继续持有当前交易对、周期、SSE 状态、备用状态和请求代次。适配层在订阅回调前校验交易对、周期及代次，使切换后的旧历史响应或实时事件无法写入新图表。若 Pro 的 Datafeed 回调不足以表达现有 hasMore/错误状态，适配层通过经验证的图表 API 补充分页触发和状态呈现，不把状态降级交给 Pro 的连接提示。

备选方案是把 SSE、REST fallback 和状态判定迁进 Pro Datafeed；这会把页面行情状态耦合到图表组件，并可能把“已连接”误当成收到有效 K 线，因此保留现有协调层。

### 4. 保持浏览器偏好格式的可恢复迁移

继续把研究指标配置作为跨交易对、跨周期的浏览器共享偏好，把绘图对象按交易对存储。实现 Pro 绘图状态与现有 Core 对象之间的明确序列化映射；先迁移当前应用支持的水平线、趋势线、射线、平行通道和斐波那契回撤，并保留 Pro 新建对象的类别与锚点。迁移按版本标记、幂等执行；只有新格式成功写入后才能标记迁移完成，不删除旧存档。若锁定 Pro 的公开 API 无法读写绘图对象，则在适配层上游提交或维护最小版本化补丁暴露所需读写能力，不依赖无校验的私有字段访问。

备选方案是清空或仅恢复新建绘图；这会丢失现有规格承诺的用户绘图，故不采用。另一个备选方案是依赖内部私有字段，升级脆弱且难以做兼容验证，故只允许使用有回归测试的显式适配接口。

### 5. OI 适配只选 Binance 数量字段

前端适配器将每条 OI 样本的 `sumOpenInterest` 映射为副图数值，并保留样本时间；`sumOpenInterestValue` 不进入绘图序列。没有样本或周期不支持时返回空序列，失败继续走现有可恢复错误状态。用两个字段数值明显不同的固定样本测试映射，避免相等数据掩盖错误字段。

备选方案是继续使用名义价值或在缺少数量字段时回退到价值；这会违反用户要求并混淆单位，因此禁止回退。

### 6. 由图表区域直接承载控件，不重建自定义摘要

仅替换现有 Dashboard 右侧图表区域中的周期选择、指标操作和绘图工具；左侧 Watchlist（包括标题、布局、报价和交互）、页面主 header、全局行情状态及其他区域的 header 保持原样。右侧图表区域不再显示应用自定义标题和摘要中的当前价、涨跌幅、高低价、加载区间成交量及 ATR；图表自身的十字线数据和指标图例不属于该摘要。指标配置继续使用现有共享偏好规则，不能因 Pro 的默认本地状态而变成逐交易对或逐周期设置。

Pro 只挂载在当前右侧图表区域，不改动 Dashboard 外壳或 Watchlist，以保持页面其他 header 的布局与行为。

备选方案是在右侧图表区域继续保留重复的自定义摘要以填补视觉空间；用户已明确要求该区域复用 Pro 样式与功能，且重复栏位会形成两套相互竞争的控件，故不采用。

## Risks / Trade-offs

- [Pro 与 Core 的有效版本组合或 Vue 内嵌生命周期不兼容] → 在依赖变更前完成最小运行验证并锁定组合；验证失败时先调整兼容版本/适配方式，不绕过类型或运行时错误。
- [Pro Datafeed 没有现成的向前分页或状态钩子] → 兼容性阶段验证实际拖到左边界的请求；在已验证 API 上加薄适配，保留项目现有游标和 hasMore 逻辑。
- [Pro 未公开绘图序列化 API] → 为目标版本加显式、最小的适配 API 并锁定版本；对旧对象逐类做往返和迁移测试，迁移失败保留旧存档。
- [Pro 的指标菜单不支持自定义 OI 或现有参数校验] → 在注册阶段验证自定义副图和参数表单；通过适配入口接入现有 OI 与参数校验，不另建长期并列工具栏。
- [移除摘要后用户看不到原有 ATR、高低价和加载区间成交量] → 这是提案明确的可见行为变化；不把这些值暗中搬入另一条自定义摘要。
- [Pro 更新改变工具行为或 Datafeed 契约] → 固定依赖版本，升级时要求适配层和绘图迁移回归通过。

## Migration Plan

1. 先验证 Pro/Core 版本组合和 Datafeed、分页、绘图读写接口；兼容性不通过时不改页面实现。
2. 先提交覆盖 Datafeed 生命周期、OI 字段映射、偏好迁移及控件交互的前端行为测试，并观察待实现行为失败。
3. 接入并锁定依赖，逐步替换自定义图表控件，维持现有历史、实时与备用数据协调。
4. 按交易对惰性迁移绘图偏好；成功写入新版本后记录迁移版本，旧数据至少保留一个兼容周期。
5. 完成前端自动化回归、类型检查和生产构建，并在本地验证切换标的/周期、实时更新、绘图保存恢复及 OI 数量显示。

回滚时恢复旧图表组件和依赖锁定版本；迁移过程保留原绘图存档，因此旧版可继续读取。若新 Pro 数据已保存，回滚适配器应继续保留新格式，避免清理用户绘图。
