## Context

动机参见 `proposal.md`；行为契约参见两个增量 spec。当前前端交易对列表位于 Pinia store，页面通过下拉框切换；K 线、分析和交易机会请求直接传递 `symbol`，而 SSE 处理器有独立的 8 币白名单。页面把 `EventSource.onopen` 当成实时连接成功，但 SSE 在 Binance WebSocket 建立之前就会发出 `ready`。后端复用同一交易对/周期的上游连接并在断开后重试，前端另有 60 秒 REST 刷新。

## Goals / Non-Goals

**Goals:**

- 在不增加数据库或新服务的前提下，让自选交易对贯穿现有四条数据路径。
- 将“浏览器已连 SSE”与“已收到上游价格”分开，令断流可见且有恢复路径。
- 切换交易对和周期时，不让旧响应覆盖当前行情。

**Non-Goals:**

- 不实现全量交易对搜索、跨设备同步或用户账户。
- 不保证网络完全中断时仍能得到新价格；此时保留旧数据并标明过期。
- 不改动技术指标计算算法或交易机会判定逻辑。

## Decisions

### 1. 通过后端统一校验 Binance 合约交易对

新增一个轻量的交易对校验入口供前端添加自选时调用，并让现有 K 线、分析、交易机会、SSE 处理器复用相同的规范化和校验逻辑。规范化包括去首尾空白和转大写；格式错误返回 400，格式正确但不处于可交易状态返回 404，交易所校验暂不可用返回 503。通过 Binance 合约交易对元数据判断是否可交易，并短时缓存结果，避免每次行情请求都拉取完整列表。缓存失效且刷新失败时返回 503，不把未知新币误判为不支持。校验通过后，真正的上游行情调用仍须处理交易所状态变化和网络错误。

备选：仅在前端限制格式、后端直接请求 Binance。该方案无法在开启 SSE 前可靠地区分无效交易对与上游连接故障，也无法统一不同 API 的反馈。

### 2. 自选列表保存在浏览器，服务端无自选状态

Pinia store 合并现有预设列表与 `localStorage` 中的自选列表。添加前调用校验入口；按规范化后的交易对去重。读取本地存储时校验结构并去重，损坏数据退回空列表。删除当前选中的自选交易对时切回默认预设交易对。服务端不存用户偏好。

备选：写入 SQLite。当前应用没有用户身份，服务端存储会让不同浏览器共享一份列表，并增加额外 API 与迁移工作。

### 3. 把行情来源和新鲜度建模为页面状态

页面维护 `connecting`、`live`、`fallback`、`unavailable` 状态，以及最近一次成功接收当前交易对行情的本地时间。`ready`/`onopen` 只表示 SSE 建立；仅匹配当前交易对和周期的 `kline` 事件使状态进入 `live`。后端 SSE 增加上游连接失败/重试状态事件，供页面及时提示，且保留现有 `ready` 和 `kline` 事件兼容性。客户端也独立计算距上一条实时事件的时间，避免上游握手卡住但 SSE 一直打开时出现假连接。

备选：只依赖 `EventSource.onerror`。该事件只能反映浏览器到后端的连接，无法检测后端到 Binance 的 WebSocket 停滞。

### 4. 在无实时事件时做有界 REST 备用更新

启动或切换交易对后若 15 秒仍无实时 `kline`，进入备用路径；之后约每 15 秒拉取当前交易对最新 K 线，避免并发重叠请求。实时事件恢复后停止高频备用请求，保留现有较慢的分析刷新。备用成功显示 `fallback` 及最近获取时间；备用失败显示 `unavailable`，保留旧数据供参考。上游 SSE 仍由服务端重连，浏览器 SSE 断开由 `EventSource` 重连。交易对或周期变化时取消旧订阅、停止旧定时器，并用请求代次丢弃晚到的结果。

备选：把所有行情统一改为固定高频轮询。它会失去现有实时事件的低延迟，并给 Binance REST 增加持续负载。

## Risks / Trade-offs

- [Binance 合约元数据请求失败或交易对下线] → 分别返回可恢复错误或不支持错误；UI 保留已保存条目供用户删除，不静默切换为其他币。
- [冷门交易对长期没有成交事件] → 超时后标示“备用更新”，不宣称 WebSocket 价格实时；备用拉取成功仍显示其独立接收时间。
- [多标签页同时订阅增加 REST 负载] → 仅在没有实时事件时启动短间隔备用请求，并限制每页同一时刻只有一个请求；服务端维持现有 WebSocket 共享机制。
- [本地存储不可写或内容损坏] → 当前页面仍可使用预设交易对，并提示自选列表未能持久化。
- [部署网络无法访问 Binance WebSocket] → 界面明确显示备用/不可用状态；部署验证分别覆盖 REST 和 WebSocket 连通性，不把 SSE `ready` 当成上游成功。

## Migration Plan

自选列表首次部署时为空，现有预设和默认 ETHUSDT 继续可用。新 SSE 状态事件为增量事件，旧客户端仍可消费 `ready` 与 `kline`。发布后验证新增交易对、实时推送、上游受阻时的备用更新及恢复；回滚前端和后端即可恢复原行为，浏览器保存的自选列表不会影响旧版本的预设列表。
